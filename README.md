# Predictive Journey Planner Using AI for Future Traffic and Route Optimization

A journey-planning application that helps travelers organize departure details, explore route alternatives, and compare their options in one place. Its product roadmap includes AI-powered traffic forecasting and route optimization.

## Product overview

Predictive Journey Planner brings journey details and route exploration into a responsive interface.

- Plan a journey with a starting location, destination, travel date, and departure time.
- Validate required fields, distinct locations, and future departure times.
- Review and edit journey details from a dedicated Results view.
- Compare illustrative routes between Shivajinagar, Pune and Pune Railway Station in either direction.
- Select route alternatives and view the highlighted route on an interactive map.
- Navigate with browser Back and Forward, keyboard controls, and responsive layouts.

Journey details stay in memory until the page is refreshed. Opening or refreshing Results without saved journey details returns to the planning form.

## Current availability

Route exploration currently uses predefined demonstration corridors in Pune. These schematic routes are not verified road directions. Unsupported locations retain the journey summary and display a route-unavailable message.

Live traffic predictions, travel durations, distances, delays, arrival estimates, and departure recommendations are not currently available. Backend services and AI forecasting are planned capabilities. Map tiles are provided by OpenStreetMap and require an internet connection; schematic routes remain available when tiles fail to load.

## Run on Windows

Install Node.js 24 LTS, which includes npm. Open PowerShell or Command Prompt in this project directory:

```sh
cd frontend
npm ci
npm run dev
```

Open the local address printed by Vite. Press Ctrl+C to stop the server.

To run automated checks, use these commands from `frontend/`:

```sh
npm test
npm run lint
npm run build
npm audit
```

`npm run preview` serves the production build locally after building.

Tests use Node's built-in test runner and cover journey validation, local departure times, supported demonstration routes, and reverse-route geometry. They do not replace browser testing of navigation, maps, or responsive layouts.

`App.jsx` owns in-memory journey state and browser navigation. Pages compose the views; components contain form, summary, navigation, and map interactions. `data/` contains explicitly labeled demonstration routes and shared navigation definitions. `utils/` contains journey normalization and validation independently of React. Tests live next to the behavior they verify.

The root `.gitignore` covers dependencies, build output, local environment files, logs, and editor settings throughout the repository. `frontend/node_modules/` is generated by installation; `frontend/dist/` is generated by the production build. Both are excluded from version control. The lockfile is maintained to keep dependency installation reproducible.

## Integration boundaries

The repository currently contains the frontend. There is no backend service or API integration yet. Keep server implementation separate from `frontend/` when backend work begins, and keep service credentials out of browser code. Frontend validation improves input feedback; a future API must validate requests independently.

The application uses JavaScript with React, Vite, and React Leaflet. React type definitions support editor suggestions; the application source is JavaScript.
